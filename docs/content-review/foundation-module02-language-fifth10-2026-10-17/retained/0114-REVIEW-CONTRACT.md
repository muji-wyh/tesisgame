# Independent helper-source review contract

An independent reviewer must inspect the exact helper inventory and every inventoried member before any execution. Use a new review directory; preserve all earlier packets. The helper author, inherited preparation author and dispatcher cannot provide this acceptance.

The acceptance JSON must contain these exact fields and values, with a complete concrete pin for `source_inventory`:

```json
{
  "schema": 1,
  "status": "accepted_for_one_root_owned_fifth10_binding_capture",
  "reviewer": "/root/morph_review",
  "source_inventory": {"path": "build/professional-english/foundation02-fifth10-root-binding-proposal-r01/source-inventory.json", "bytes": 0, "raw_sha256": "REPLACE_WITH_ACTUAL_REVIEWED_INVENTORY_HASH"},
  "helper_execution_accepted": true,
  "actual_binding_accepted": false,
  "preparation_execution_accepted": false
}
```

This example is not an acceptance. The byte count and hash are deliberately unusable. The reviewer must use their actual canonical `/root/<agent_name>` identity; `/root`, `/root/recover_delivery`, and `/root/runtime_recovery` are rejected. The source-inventory pin must exactly equal the root capture input's pin, including path, byte length and hash. Add findings, scope, review evidence and limitations as appropriate. Root may pin these supporting records individually in `additional_review_evidence`.

Review the built-in-only call graph, copied genuine predecessor journal checks, original/copy receipt equality, complete input union, exact final registry construction, retained history, target/absence closure, guards, one-shot output, and lack of preparation or project execution. `guard-cases.json` describes unexecuted negative specifications; it is not a test result or execution claim.

This acceptance authorizes source use only for the stated capture. The resulting binding still requires a different exact-artifact acceptance satisfying the frozen preparation r03 contract. It must not be relabeled as preparation approval.
