# IT Support expert-review brief

## Status and scope

The integrated draft contains 500 distinct canonical senses and 100 expressions: the shared 100/20 foundation plus 400 specialist memberships and 80 specialist expressions. Each module contains exactly 50 senses and 10 expressions. The specialist expansion creates 243 senses and reuses 157. Independent editorial review closed five identified wording issues; it does not constitute domain, language, morphology, or media release approval. All modules and required reviews remain pending.

Every specialist sense has a scored route in its own module. The 216 new pending graphs comprise 10 explicit atomic decisions and 206 composite decisions. The other 27 analyses remain null and have contextual Phrase assessment. Successful spelling reconstruction does not establish the semantic validity or teaching value of an analysis.

The course supports communication about systems, accounts, problems, records, and responsibilities. It does not provide repair training, commands, access-bypass methods, configuration recipes, erasure procedures, security certification, or guaranteed recovery. All new picture-suitability flags are false. A support scene or technical diagram must not become an isolated picture-identification exercise without review.

## Review assignments

| Area | Required decisions |
|---|---|
| Equipment | Verify device, component, connector, and tool meanings at gameplay size. Headphones do not imply a microphone; headset does. A power supply is broader than a voltage-converting adapter. Illustrations cannot imply that the learner is authorized to repair or dismantle equipment. |
| Systems and networks | Distinguish working memory, persistent storage, memory module, disk space, and memory usage. Verify logical volume, network port, default gateway, file synchronization, and system requirements. A default gateway is the router or next-hop address for destinations without a more specific matching route; file synchronization is not defined as backup. |
| Actions | Confirm the technical senses of scan, upgrade, reproduce, recover, reset, and quarantine. Security scan differs from reading a physical code, a software upgrade differs from a booking upgrade, and digital quarantine is an isolation-state noun. Language describes authorized work without providing an operational procedure. |
| Access and configuration | Distinguish permission, authentication, authorized access, privileged access, account activation, consent record, access control, and permission setting. A record alone cannot establish valid consent. Unsupported software includes software that was never supported by the relevant organization or provider. |
| Problems and verification | Distinguish a symptom from a confirmed cause, and data loss from a temporary connection or permission failure. Data loss can concern loss, destruction, or corruption without guaranteeing that recovery is impossible. Restore, workaround, validation, and resolved status must not imply an unverified result. |
| Security and equipment lifecycle | Distinguish vulnerability from threat. Verify reporting and authorization boundaries for phishing, malware, permissions, privacy, device disposal, and sanitization. Disposal means relinquishing or discarding through applicable arrangements; retirement into storage is insufficient. No erasure, recycling, dismantling, or incident-response procedure is taught. |
| Recovery | Verify the shared recovery point objective as a target for how recent restored data must be, often expressed as maximum acceptable data loss. It is not backup retention. Keep recovery time, recovery point, actual restoration evidence, and promised service arrangements distinct. |
| Records and interfaces | Confirm interface button, prompt, resolution, architecture, certificate, service, knowledge article, and record meanings. Fictional media must contain no real credentials, personal records, or organization identifiers. |
| Coordination | Verify assignment, escalation, service communication, handoff, change, incident, and follow-up terminology against launch-region practice. Existing generic senses are reused where meaning and POS match. Metrics describe their stated basis and do not establish guaranteed performance. |
| Accessibility and English variants | Verify captions, screen readers, assistive technology, high contrast, keyboard use, and individual preferences. Accessibility cannot be inferred from the presence of one feature. Regional alternatives and difficulty labels are candidates, not additional inventory entries or certified CEFR levels. |
| Morphology | Confirm each authored constituent, allomorph, prefix, suffix, compound, and phrase boundary. Review computing ware, hardware, firewall, network, subnet, upgrade, and ransomware for semantic transparency and lexicalization. DHCP remains an abbreviation. Null and atomic are different decisions; do not substitute syllables, spelling length, or an indiscriminate suffix rule. |
| Media | Acquire and inspect each image and recording, record source, creator, license, acquisition status, and animations, and review at gameplay size. Audio retains ava-sweet: en-US-AvaNeural, rate -15%, pitch +8Hz, volume +0%, no postprocessing. |

## Shared identities and corrections

Education reuses thirteen IT-owned senses: headphones, permission setting, access control, file upload, save, shared folder, secure message, consent record, data export, screen reader, caption, assistive technology, and authorized access. File upload is a noun, while upload is a distinct existing verb. These share canonical IDs and progress records across courses.

Office, Warehouse, and Hospitality module09 now use the interface button instead of the clothing fastener. Retail's clothing sense remains unchanged. Those same three courses' module10 now use `handover-meeting.meeting-for-transfer-of-work-information-and-responsibility.n`, an event for transferring work information and responsibility. The care-only handover note remains in Nursing and Caregiving. Handoff summary and handover checklist remain distinct records. Contextual references moved to the correct sense, and each corrected membership has a same-module Phrase focus. Earlier physical-dimension and prerequisite-dependency corrections now also have local Phrase focuses.

The shared recovery point objective definition and image brief were clarified using the actual NIST glossary definition. Its identity, pending review gates, morphology, and media status were preserved. No progress migration is required for these unshipped draft modules.

## Consulted evidence and limits

Seven IT sources are registered under `it-support-` IDs, and the additional shared correction uses `nist-recovery-point-objective`. The registry records exact URLs, publishers, consultation dates, scope, and the absence of asset acquisition. The occupational, troubleshooting, security-reporting, and accessibility pages support context, not term-by-term certification.

The independent reviewer specifically consulted [Microsoft Get-NetRoute](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-netroute?view=windowsserver2022-ps), including the description and default-route example; [NIST vulnerability](https://csrc.nist.gov/glossary/term/vulnerability); and [NIST Recovery Point Objective](https://csrc.nist.gov/glossary/term/recovery_point_objective). Microsoft commands were neither run nor copied into lessons. Linked NIST standards were not reviewed in full. A Dictionary.com subnet origin entry was mathematical and did not validate the networking analysis; an American Heritage ransomware page did not establish enough boundary evidence to approve that graph. Neither attempted lexicographic check is represented as morphology approval.

Record reviewer name, qualification, date, region, source edition, exact canonical or expression ID, decision, and revised wording before changing a gate. Domain review, language review, morphology, picture suitability, pronunciation, asset provenance, packaging, and full-theme readiness require separate evidence.
