### Morphology graph

The morphology contract is shared with the runtime composition resolver:

~~~json
{"schema": 1, "id": "...", "lexeme_id": "...", "text": "...", "kind": "...", "review": {}, "parts": [], "nodes": [], "roots": []}
~~~

Parts are ordered occurrences, each with a unique local ID, a reusable canonical_id, a typed role, canonical form, and exact surface text. Types distinguish roots, stems, affixes, compound elements, combining forms, lexical words, atomic words, and abbreviations.

Earlier draft graphs use morph.<canonical> for ordinary bases, affix.<form>.<prefix-or-suffix> for affixes, and abbr.<canonical> for abbreviations. The later source-backed tranche records explicit identities such as english.affix.ad.toward and english.root.tract.pull, including the at- surface of ad- in attract. A spelling match alone is not proof of a shared morpheme: the remaining generic identities need an individual sense and family audit. No bulk identity migration is implied by these candidate graphs.

Nodes identify left and right inputs and an exact resulting surface. A named rule documents the editorial spelling decision; it is not a heuristic. Roots must cover all original parts in their original order and reproduce the full lexeme exactly. ## Validation and development workflow

Run the authoring audit:

~~~powershell
node tools/validate-professional-content.cjs
~~~

Run the strict release gate:

~~~powershell
node tools/validate-professional-content.cjs --release
~~~

Add --json to obtain every issue with its code, path, and message. The draft audit exits successfully only when structural and referential integrity holds. It reports incompleteness as warnings and release_ready false. The strict release gate exits nonzero for missing inventories, reviews, media, themes, or scored exercise routes.

A ready module or theme triggers the corresponding strict checks even during a draft audit. Changing a status label cannot turn pending content into release-ready content.

The module exports:

- auditProfessionalContent({rootDir, release, data}): audit result with ok, errors, warnings, and coverage summary; the optional data argument supports in-memory test fixtures.
- loadProfessionalContent(rootDir): canonical content plus source-file indexes.
- schemaErrors(value, schemaName): JSON contract errors.
- morphologyErrors(analysis, lexeme): graph, identity, spelling, order, and coverage errors.
- resourcePath(rootDir, resource): checked local resource resolution.

Run the regression tests:

~~~powershell
node --test tests/professional-content.test.cjs
~~~

The tests cover fail-closed release behavior, twenty complete career draft inventories, mandatory care, food, customer-service, office, warehouse, hospitality, transport, IT, education, HR, construction, cleaning, manufacturing, marketing, clinical, financial, and legal domain review, shared foundation consistency, canonical sharing and distinct senses across careers, on-demand file links, synonym and inflection padding, regional roles and alternatives, malformed morphology, spelling changes, long terms and repeated constituents, possessive-clitic identity, intact initialisms, repeated phrase tokens, phrase-skill linkage, unsupported phrase exclusion, ambiguous picture exercise exclusion, atomic exposure, source limitations, asset provenance and hashes, safe paths, complete content and theme dependencies, immutable media paths, local Home preview scope and budgets, theme mappings, and exact voice settings.

This content validator does not prove clinical or linguistic correctness, artwork quality, gameplay integration, bundle size limits, cache behavior, or responsive layout. Those require the recorded reviews and the implementation and release checks in the complete development plan.
