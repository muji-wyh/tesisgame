# Loading and game interaction fixes

## Reported problems and changes

The user reported unresponsive loading clicks, inaccurate loading progress, confusing
My rewards navigation and inconsistent interactions inside the game.

- Loading progress now uses the engine's actual byte counts. Unknown totals remain
  indeterminate; completed downloads change to Starting game, and only the game's
  ready callback completes startup. Slow startup exposes Try again. Synchronous
  engine failures and graphics context loss show the accessible recovery screen.
- Repeated Pip clicks have distinct text feedback even with reduced motion. Lost
  pointer capture cancels an interrupted treasure gesture.
- My rewards has separate Pip's room and Medals tabs, with one Back route. Switching
  sections resets scrolling, and closing a medal preview returns to Medals. Locked
  toy and room previews explain the requirement and expose Back to my room. Trying
  a newly unlocked gift always opens the room containing it.
- Changing a lesson, correction, game prompt or room toy stops the old word audio.
  Memory correction pronounces the picture currently displayed. Leaving speech mode
  or opening rewards stops automatic correction advancement. Sky and Listen restore
  the visible feedback and Continue instruction when returning from rewards.
- A failed reward read leaves practice usable and exposes Retry rewards. A failed
  victory save preserves its pending piece and blocks losing that piece. Repeat and
  New adventure save an unopened victory piece before replacing the round.
- Mouse wheel distance follows the actual input amount, and wheel release no longer
  scrolls a second time.

## Validation

The game remains on Godot 4.7.1 with its existing assets and save formats. Validation
uses a separate preview on port 4181; the user's port 4173 preview is preserved.
New regression cases first reproduced audio, recovery, navigation and loading defects.
Native tests cover actual viewport input for Retry, plus saving, focus and modal state.
Browser tests use real touch, keyboard and controller events and the game's public
announcements. Screenshots cover 320-pixel portrait, phone portrait and landscape.

- The full native and Node command passed: 23 Godot suites, 11,851 checks, plus
  89 Node tests. The one optional external Unity source-pack checksum case keeps its
  existing skip because that source archive is unavailable.
- A subsequent landscape audit reproduced an offscreen preview return button when
  it already held focus. Explicitly ensuring its visibility after layout fixed the
  defect; the expanded navigation suite passed 16 checks. Final Chromium screenshots
  and a real touch on the now-visible button verify the rendered result.
- The loading matrix passed all 78 cases across Chromium and two WebKit profiles.
- Browser recovery passed 9 cases across the same profiles. That pass found a
  duplicated save-error message overlapping Retry saving. The detail moved to the
  button tooltip; the result page keeps its short recovery instructions. Native
  recovery passed 53 checks after the fix.
- Final export recovery checks passed on all three profiles. Real Retry touches,
  restored writes and Repeat preserve exactly one earned piece. Final failure-page
  screenshots show the full button without overlap.
- Final UI tours passed two targeted Chromium cases and all four WebKit cases
  (three screen sizes plus locked previews), including a real landscape return touch.
- Existing WebKit reward regressions passed six cases: four-round medal assembly
  and persistence, deliberate touch versus swipe, and preview celebration on phone
  and tablet. Adventure-book desktop checks passed three cases; Medals scrolling
  passed four, retaining 1:1 finger tracking at DPR 1/2/3 and inertia cancellation.

The broad desktop run exposed an obsolete audio expectation: it required a delayed
`correct` pronunciation to start after Continue had dismissed that correction. The
new cancellation deliberately prevents this. Both failed traces returned the music
and voice downloads successfully within 15 seconds, ruling out network timeout. The
test now requires exactly one resumed stream (current music), with no stale voice;
the isolated regression passed. No game code or export changed for this correction.

Desktop gameplay coverage completed 70 cases across the runs: 62 passed in the
63-case broad run, its obsolete audio case passed after the exact assertion update,
and the seven adventure/scroll cases passed separately. The broad run took 10.9
minutes. No unresolved regression failures remain.

Local evidence is retained in `build/qa-ui-desktop-final`,
`build/qa-held-audio-current-cue`, `build/qa-ui-final-chromium`,
`build/qa-ui-final-webkit`, `build/qa-medals-scroll-final`,
`test-results/ui-recovery-final-desktop`, `test-results/ui-recovery-final-webkit`
and `test-results/reward-webkit-final`. Source review and `git diff --check` found no
release blockers.

## Limits

The WebKit profiles run on Windows; they are not physical iPhone or iPad tests. The
existing Windows WebKit screenshot limitation after viewport resizing remains as
documented in the Memory Garden release notes. See the loading evidence report for
measured download bytes and the main-thread pause during engine initialization.
