# Interface button click review

Date: 2026-10-07

## Scope and source

Non-gameplay controls share the short click extracted from the first five
seconds of the user's `sound_effect-select.mp4`. The selected excerpt starts
at 2.190 seconds and lasts 80 ms. The [asset record](../assets/ui-click-audio.md)
and [manifest](../assets/ui-click-audio.json) document its source, acquisition
status, processing, signal levels and hashes. The source recording and extracted
WAV remain outside public Git content; the compiled game and loading page
include the validated recording.

Coverage includes the loading page, game library, settings, room navigation,
player management, leaderboards, result actions and Voice Pop navigation.
Gameplay cards, pronunciation, hints, Memory peeking, chest holds and Pip/toy
play retain their own feedback. Accepted pointer, touch, keyboard and controller
actions play once; disabled controls, canceled gestures, drags and duplicate
touch/mouse releases do not add a click. Navigation preserves the short tail.
Saved and live mute, hidden-page cleanup and diagnostic mix apply to the cue.

## Native, host and export checks

- All 308 Node tests passed, with no failures or skips. New tests cover source
  validation, packaging, host activation routing and pending-play lifecycle.
- All 14 selected native suites passed after focused rechecks of the two initial
  failures. The new UI click suite passed 55 checks; the mode-menu regression
  suite passed 210 checks. Other suites covered audio flow/recovery, presentation,
  room navigation, ages, leaderboards, player management, Voice Pop, rewards and
  retained Pip/gameplay audio behavior.
- Rechecks corrected an assertion that outlived the 80 ms clip and verified the
  fix for emulated mouse presses arriving before their matching raw touch.
  Playback requests and natural completion now verify navigation behavior
  without depending on a short-lived `playing` flag after expensive UI rebuilds.
- The final Web export validated 112 required audio resources, all 350 word
  pronunciations and absence of retired-mode resources. Startup payload is
  27.08 MB. The build receipt verified 2,232 source inputs and 17 unchanged
  output files.

## Browser checks

All seven selected desktop Chromium cases passed against the final export.
The new loading-page test verifies actual media playback for mouse, touch,
Enter, Space, arrow keys and controller actions, including an Enter tail that
survives the page transition. It verifies one player, gain 0.48, playback rate 1
and natural completion; programmatic clicks and loading toys add no UI cue.

The native-menu test verifies the exact WAV through WebAudio, one playback per
accepted action, no added UI cue on gameplay cards, and mute synchronization
with browser diagnostics. Existing library navigation/preferences, loading Pip,
Match timing and Memory timing checks also passed. The retained desktop menu
capture was inspected with controls visible and aligned.

Both selected iPhone WebKit cases passed: library navigation across sizes and
games, and sound/motion preferences across reloads. The retained mobile canvas
capture was inspected. Windows WebKit has no WebAudio in this setup, so these
checks validate touch, layout and state; Chromium supplies the audio evidence.

The extraction review used source frames, waveform boundaries and signal levels.
Audio input is unavailable to the agent, so this review does not claim subjective
listening. Runtime checks verify actual playback, exact recorded buffers,
duration, gain, playback rate, repeat behavior and channel lifecycle.
